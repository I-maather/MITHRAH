# Anti-Hallucination Architecture — بنية منع الهلوسة

**الكود:** `backend/app/llm/` (معزولة) · `backend/app/intelligence/` (حتمية)

---

## 1. تقسيم الصلاحيات — لا سلطة تنفيذية لنموذج لغوي

### ممنوع على النموذج اللغوي أن يحسب أو يخترع

سعراً · مؤشراً · إصداراً اقتصادياً · خبراً · مستوى دعم أو مقاومة · كمية ·
مسافة وقف · جني أرباح · سبريداً · هامشاً · قيمة نقطة · مخاطرة · R:R ·
درجة ثقة · موافقة على صفقة · جسم أمر للوسيط.

### مسموح له

تلخيص بيانات مُهيكلة مُتحقَّق منها · شرح استنتاج حتمي · الترجمة إلى العربية ·
Morning Brief · شرح `WHY_TRADE` و`WHY_NO_TRADE` · مقارنة الظروف الحالية بأنماط
تاريخية **مخزَّنة سابقاً**.

**استجابة نموذج لغوي لا تستطيع تعديل قرار تداول — أبداً.**

---

## 2. لماذا هذه ضمانة بنيوية لا تعليمات

| الضمانة | كيف |
|---|---|
| لا يستطيع الوصول للتنفيذ | `app/llm/` لا تستورد وسيطاً ولا تنفيذاً ولا محرك مخاطر ولا Kill Switch — **مُختبَر بتحليل AST للاستيرادات** |
| لا يستطيع إعادة قرار | عقد `SummaryProvider.summarize` يعيد `str` **فقط** — لا شكل إرجاع يحمل قراراً |
| يعمل بعد القرار لا قبله | `finalize()` تُستدعى على نتيجة **نهائية**، وتضيف حقول عرض فقط |
| لا يستطيع إدخال رقم | كل رقم يُقارَن بالسجل المُتحقَّق منه قبل العرض |

---

## 3. ضوابط منع الهلوسة

- مخططات مُصنَّفة صارمة (Pydantic مجمّدة + dataclasses مجمّدة)
- مخرجات محصورة بقوائم `Enum`
- طوابع زمنية إلزامية
- نسب مصدر إلزامي لكل قيمة (`Sourced`)
- `UNKNOWN` قيمة صالحة في كل مكان
- تحقق من المدى العددي
- فحوص اتساق عبر الحقول
- حسابات حتمية بالكامل
- رفض البيانات القديمة
- لقطات غير قابلة للتعديل
- مستويات موثوقية للمصدر
- حجب الأسرار في كل مخرج
- تجهيزات اختبار لمعلومات مشوَّهة
- **عزل مخرجات النموذج**
- **لا صلاحيات وسيط للنموذج**

---

## 4. رقم مختلَق ⇒ `HALLUCINATION_DETECTED`

```
ملخص النموذج
    ↓
استخراج كل رقم منه (بعد إزالة رموز بنيوية مثل H4 و M15)
    ↓
مقارنته بكل رقم في السجل المُتحقَّق منه
    ↓
رقم غير موجود؟
    ├─ وسم HALLUCINATION_DETECTED
    ├─ **طرح الملخص كاملاً**
    ├─ توليد شرح قالبي حتمي بدلاً منه
    ├─ **القرار الأساسي لا يتأثر**
    └─ تسجيل الحادثة بلا أي بيانات حساسة
```

`decision_changed` في نتيجة الحارس **قيمتها `False` في كل مسار** — مُختبَر.

---

## 5. مناقضة القرار ⇒ `LLM_CONTRADICTION`

إن ادّعى الملخص صفقة والقرار الحتمي `NO_TRADE` (أو العكس، أو ادّعى صفقة
والنظام `HALTED`):

- **القرار الحتمي يبقى الحاكم**
- يُعرض الشرح الحتمي
- تُسجَّل الحادثة `LLM_CONTRADICTION`
- **لا تداول بناءً على مخرج النموذج**

---

## 6. غياب النموذج ليس عطلاً

```
النموذج غير متاح · أو عطل فيه · أو ملخص فارغ
    ↓
الخط الحتمي يستمر كما هو تماماً
    ↓
تقرير قالبي مُهيكل بلا نموذج
```

الشرح القالبي هو الشرح **الافتراضي**، لا احتياطياً متواضعاً: كل رقم فيه مأخوذ
حرفياً من السجل الحتمي، ولذلك يجتاز فحص الحارس دائماً بالتعريف (مُختبَر).

---

## 7. تسجيل الحوادث بلا بيانات حساسة

قيد الحادثة يحمل: نوعها · وقتها · عدد الأرقام المختلقة وقيمها (حتى عشرة) ·
القرار الحتمي وقتها. **لا مفاتيح ولا رموز جلسة ولا معرّفات حساب** — مُختبَر.

---

## 8. الخريطة الكاملة: من يحسب ماذا

| القيمة | من يحسبها |
|---|---|
| السعر والسبريد | **Capital.com** (المرجع الوحيد) |
| المؤشرات | كود حتمي محلي من شموع مُتحقَّق منها |
| الأحداث والأخبار | مزوّدون مُعرَّفون بنسب كامل |
| نظام السوق | `classify_regime()` حتمي |
| الاستراتيجية | `match_strategy()` حتمي، واحدة أو لا شيء |
| الكمية والوقف والهدف | `SetupBuilder` + `PositionConstructor` حتميان |
| التكاليف والمخاطرة و R:R | `CapitalComCostModel` حتمي |
| درجة الجودة | `evaluate_quality()` حتمي بأوزان معلنة |
| التناقضات وحلولها | `detect_contradictions()` حتمي بحلول مكتوبة مسبقاً |
| المراجعة المستقلة | `IndependentTradeVerifier` حتمي |
| القرار | خط المراحل السبع عشرة |
| **الصياغة العربية للشرح فقط** | **النموذج اللغوي — إن توفر واجتاز الحراسة** |
