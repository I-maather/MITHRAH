# TradingView Position — موقف TradingView

**القرار: TradingView ليست محرّك التنفيذ، ولا تدخل المسار الحرج.**

---

## 1. ما هو مقرر لهذا الإصدار

| البند | القرار |
|---|---|
| اشتراك مدفوع | **غير مطلوب** |
| إرسال أوامر عبر TradingView | **ممنوع** |
| Pine Script ينفّذ لدى الوسيط | **ممنوع** |
| الاعتماد عليها في SL أو TP أو الخروج الطارئ | **ممنوع** |
| مصدر بيانات التنفيذ | **Capital.com REST و WebSocket حصراً** |
| استعمالها كتصوّر بصري للمالكة | مسموح، خارج النظام |

---

## 2. لماذا

1. **مصدر واحد للحقيقة.** أسعار التنفيذ والتأكيد والمطابقة يجب أن تأتي من الوسيط
   الذي ينفّذ فعلاً. سعر من طرف ثالث قد يختلف عن سعر التنفيذ.
2. **الخروج الطارئ لا يعتمد على طرف ثالث.** إن سقط webhook أو تأخر، يجب أن يبقى
   وقف الخسارة **موجوداً عند الوسيط نفسه**.
3. **سطح هجوم أقل.** كل مسار خارجي يقبل طلبات هو باب.
4. **جودة الاختبار.** إضافة تعقيد الآن يقلّل جودة اختبار Capital.com دون فائدة.

---

## 3. ما بُني رغم ذلك — بابٌ مغلق ومُختبَر

`backend/app/signals/source.py` يوفّر `SignalSource` و`SignalInbox`
و`TradingViewWebhookSource` — **معطّلاً افتراضياً** (`enabled=False`).

أي webhook مستقبلي يجب أن:

| الشرط | الحالة | الاختبار |
|---|---|---|
| معطّل افتراضياً | ✅ | `test_tradingview_source_is_disabled_by_default` |
| يوثّق الطلبات (HMAC) | ✅ | `test_bad_signature_is_rejected` |
| يرفض التنبيهات القديمة | ✅ | `test_stale_alert_is_rejected` |
| يرفض التنبيهات المكررة | ✅ | `test_duplicate_alert_is_rejected` |
| يدخل صندوق وارد | ✅ | `test_valid_signed_alert_enters_the_inbox_only` |
| يمرّ عبر محرك الاستراتيجية | ✅ (بنيوياً) | `test_signal_module_never_imports_a_broker_adapter` |
| يمرّ عبر محرك المخاطر | ✅ | نفس الاختبار |
| يمرّ عبر Kill Switch | ✅ | نفس الاختبار |
| لا يحمل اعتمادات | ✅ | `test_alert_carrying_credentials_is_rejected_and_not_stored` |
| لا يُرسل مباشرة لـCapital.com | ✅ | `test_signal_module_never_imports_a_broker_adapter` |
| ليس المسؤول الوحيد عن إغلاق مركز | ✅ | الإغلاق يبقى بوقف الوسيط |

**القيد بنيوي لا نصّي:** الملف لا يستورد `CapitalComAdapter` ولا `ExecutionService`،
واختبار يقرأ نص الملف ويفشل لو ظهر أي منها.

---

## 4. لو أردتِ تفعيلها لاحقاً

1. قرار مكتوب بأن TradingView مصدر **اقتراحات** لا أوامر.
2. ضبط `shared_secret` عبر SecretProvider (لا في الكود ولا في `.env` المتتبَّع).
3. `enabled=True` في التهيئة.
4. تشغيل في وضع الظل أولاً: الإشارات تدخل الصندوق وتُسجَّل ولا تُنفَّذ.
5. مراجعة معدل الإشارات وجودتها قبل أي ربط بالتنفيذ.

حتى بعد ذلك، **المسار من الصندوق إلى الوسيط يمرّ إجبارياً** عبر محرك الاستراتيجية
ثم محرك المخاطر ثم Kill Switch. لا اختصار.
