# Data Provider Requirements — متطلبات مزوّدي البيانات

**الكود:** `backend/app/intelligence/providers.py`

---

## 1. Capital.com — المرجع الوحيد لهذه القيم

السعر القابل للتنفيذ (bid/ask) · السبريد · حالة التداول · قواعد الأداة ·
ساعات السوق · مراكز الوسيط · أوامر الوسيط · تأكيدات الوسيط.

**لا مصدر آخر ينافسه في أي منها.**

---

## 2. الواجهات المطلوبة

| الواجهة | ما تقدّمه | إلزامية للتداول الحقيقي |
|---|---|---|
| `EconomicCalendarProvider` | الأحداث المجدولة والصادرة | ✅ نعم |
| `VerifiedNewsProvider` | أخبار بحالة تحقق صريحة | ✅ نعم |
| `MarketDataProvider` | شموع مكتملة مرتبة بلا فجوات | ✅ نعم |
| `MacroDataProvider` | سلاسل كلية (تضخم، بطالة، عوائد) | ✅ نعم |
| `FundamentalContextProvider` | سياسة نقدية، فرق فائدة، risk-on/off | ⚠️ يخفض الثقة |

---

## 3. قاعدتان صارمتان

1. **لا كشط صفحات ويب عشوائية** كمصدر حقيقة في الإنتاج.
2. **لا اختراع مفتاح API ولا مزوّد.**

---

## 4. سلوك المزوّد غير المُعدّ

```
مزوّد غير مُعدّ
    ├─ التحليل المعتمد عليه يُوسَم UNKNOWN
    ├─ الأهلية للتداول الحقيقي تسقط إن كان الحقل إلزامياً
    ├─ يُعرض اسم المزوّد الناقص **بالضبط** في الواجهة والتقرير
    └─ يُسمح بالاستمرار في وضع البحث فقط، وحيث يكون ذلك آمناً
```

**نقطة جوهرية:** قائمة أحداث فارغة من مزوّد غير مُعدّ **لا تعني «لا توجد أحداث»**
— تعني **«لا نعرف»**، والقرار `NO_TRADE`. الخلط بين الاثنين هو كيف يُفتح مركز
قبل تقرير الوظائف مباشرة (مُختبَر).

---

## 5. الحقول الإلزامية لكل خبر أو عنصر كلي

```
المزوّد · الطابع الزمني الأصلي · وقت الجلب · العملات أو الأصول المتأثرة ·
مستوى الأثر · نوع الحدث · القيمة المتوقعة (إن وُجدت) · القيمة السابقة (إن وُجدت) ·
القيمة الفعلية عند الصدور · حالة الطزاجة · مرجع المصدر
```

**لا تُبرمَج نتائج الأحداث في الكود إطلاقاً.**

---

## 6. الحالة اليوم — لا مزوّد واحد مُعدّ

| المزوّد | الحالة |
|---|---|
| `EconomicCalendarProvider` | ⛔ غير مُعدّ |
| `MacroDataProvider` | ⛔ غير مُعدّ |
| `VerifiedNewsProvider` | ⛔ غير مُعدّ |
| `MarketDataProvider` | ⛔ غير مُعدّ |
| `FundamentalContextProvider` | ⛔ غير مُعدّ |

**الأثر:** `live_eligible_by_providers = False`. لا أهلية للتداول الحقيقي
من ناحية البيانات وحدها، بصرف النظر عن كل ما عداها.

هذا يظهر في `/api/intelligence` وفي صفحة **التحليل** بأسماء المزوّدين الدقيقة.

---

## 7. عند إضافة مزوّد لاحقاً

1. تنفيذ الواجهة المجرّدة المناسبة.
2. `configured` تعيد `True` **فقط** عند وجود اعتماد صالح فعلاً.
3. كل قيمة تعود مغلّفة بـ`Sourced` بنسب كامل.
4. الحقل غير المتوفر يعود `UNKNOWN` — **لا قيمة افتراضية**.
5. اختبار بتجهيزات بالشكل الرسمي — **لا اختبار يلمس الشبكة**.
6. اعتمادات المزوّد تُخزَّن بنفس آلية `secretstore/` (Keychain ← ملف 600).
