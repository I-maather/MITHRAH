# Emergency Runbook — دليل الطوارئ

> **القاعدة الأولى:** إغلاق الخطر أولاً، الفهم ثانياً، المطابقة ثالثاً.
> لا تنتظري إذن النظام. لا تنتظري تفسيراً. الإغلاق اليدوي دائماً مسار صحيح.

**الحالة الآن:** لا مركز مفتوح · لا اعتمادات مُعدّة · التنفيذ مقفل بالكود.
هذا الدليل مكتوب مسبقاً ليكون جاهزاً، لا لأن حدثاً وقع.

---

## 0. الإجراء الفوري — 30 ثانية

```
1. افتحي تطبيق أو موقع Capital.com
2. أغلقي أي مركز مفتوح يدوياً
3. أوقفي التطبيق:  Ctrl+C  أو  make stop
4. فعّلي Kill Switch من صفحة الطوارئ إن كانت الواجهة تعمل
```

**الإغلاق اليدوي لدى الوسيط أسرع وأوثق من أي أمر يرسله النظام.**
النظام قد يكون هو المشكلة.

---

## 1. تصنيف الحالة

| العلامة | الحالة | الأولوية |
|---|---|---|
| مركز مفتوح + النظام لا يستجيب | **حرجة** | إغلاق يدوي فوري |
| مركز مفتوح بلا وقف خسارة لدى الوسيط | **حرجة** | إغلاق يدوي فوري |
| حالة `UNKNOWN` بعد إرسال أمر | **حرجة** | لا إعادة إرسال — تحقق ثم إغلاق |
| كمية أو سعر لا يطابق المتوقع | **حرجة** | Kill Switch + إغلاق |
| اتساع سبريد مفرط ومركز مفتوح | عالية | إغلاق مبكر |
| اقتراب نهاية الجلسة ومركز مفتوح | عالية | إغلاق قبل التبييت |
| اشتباه تسرّب اعتماد | عالية | §5 |
| سلسلة Audit Log مكسورة | متوسطة | إيقاف الدخول + تحقيق |
| انقطاع بيانات السوق | متوسطة | لا دخول جديد |
| فشل اختبارات | منخفضة | لا نشر ولا تشغيل |

---

## 2. حالة UNKNOWN — الأخطر

**مهلة أو انقطاع بعد إرسال أمر ليست فشلاً.** قد يكون الأمر نُفِّذ.

```
UNKNOWN
  ├─ ⛔ لا إعادة إرسال. أبداً. تحت أي ظرف.
  ├─ GET /confirms/{dealReference}
  ├─ GET /positions
  ├─ فحص التطبيق/الموقع بعينيكِ
  ├─ إن وُجد مركز ⇒ أغلقيه يدوياً
  ├─ إن لم يوجد ⇒ لا تعيدي المحاولة، أوقفي وحلّلي
  └─ سجّلي الحالة كاملة
```

المحاولة مسجَّلة في `execution_attempts` **قبل** الإرسال، فحتى موت العملية
لحظة الإرسال لا يُنتج أمراً ثانياً عند إعادة التشغيل.
عند الإقلاع، `run_startup_recovery()` يعيد `allows_new_entries = False` **دائماً**.

---

## 3. Kill Switch

| البند | السلوك |
|---|---|
| التفعيل | فوري، لا يمرّ بمحرك الاستراتيجية |
| الأثر | لا دخول جديد إطلاقاً |
| إعادة التفعيل | **لا تلقائية أبداً** — لا بإعادة تشغيل ولا بمرور الوقت |
| الرفع | قرار مالكة صريح بعد تحقيق مكتمل |
| السجل | السبب والحالة الكاملة في Audit Log |

المُطلِقات (22) وسياسة كل واحد: `backend/app/killswitch/`.

**إيقاف مؤقت أخف** (لا يستبدل Kill Switch):

```
POST /api/trading/pause
POST /api/trading/resume    ← يتطلب عبارة: ارفع الإيقاف المحلي
```

`resume` يُرفض ما دام Kill Switch مفعّلاً، ولا يفتح التداول الحقيقي بحال.

---

## 4. إعادة التشغيل بعد حادث

```bash
# 1. لا تعيدي التشغيل قبل إغلاق أي مركز مفتوح يدوياً

# 2. تحقق سلامة سجل التدقيق
make verify-audit

# 3. كل الاختبارات
make test

# 4. التشغيل — يبدأ دائماً بلا صلاحية دخول جديد
make run
```

الإقلاع لا يُعيد النظام إلى «طبيعي». يُعيده إلى **حالة آمنة لا تدخل فيها**،
وأي عودة للدخول تحتاج قراراً صريحاً.

---

## 5. اشتباه تسرّب اعتماد

```
1. Capital.com ← Settings ← API ← احذفي المفتاح أو أوقفيه
   (هذا الإجراء وحده يوقف الخطر فعلياً)
2. ./scripts/configure_capital_credentials.sh --remove
3. git log -p | grep -i "CAPITAL_" للتأكد من عدم وجود قيمة متتبَّعة
4. أنشئي مفتاحاً جديداً وأعيدي الإعداد محلياً
```

**حذف المفتاح محلياً لا يُلغيه لدى Capital.com.** الإلغاء من حسابك هو الفعّال.

الرموز `CST` و`X-SECURITY-TOKEN` في الذاكرة فقط وتنتهي خلال 10 دقائق،
ولا يوجد في قاعدة البيانات عمود يمكن أن يحملهما (مُختبَر).

## 6. من يقرر ماذا

| القرار | من |
|---|---|
| إغلاق مركز في حالة طوارئ | **المالكة — بلا استئذان النظام** |
| تفعيل Kill Switch | المالكة أو النظام تلقائياً |
| رفع Kill Switch | **المالكة فقط**، بعد تحقيق |
| الخروج من `LOCKED_REVIEW` | **المالكة فقط**، بمراجعة مكتملة |
| تخفيف أي حد مخاطرة | **لا أحد** — يتطلب تعديل كود + مراجعة + commit |
| إرسال أمر حقيقي | **المالكة، لكل أمر على حدة** |

النظام لا يملك مساراً واحداً يخفّف حداً أو يستأنف بعد إيقاف.

---

## 7. ما لا يُفعل في الطوارئ

- ❌ إعادة إرسال أمر بعد مهلة
- ❌ فتح مركز معاكس «للتحوّط» — التحوّط ممنوع بالكود
- ❌ زيادة الكمية أو توسيع الوقف لتفادي تحقق الخسارة
- ❌ تعطيل حد مخاطرة أو Kill Switch لإخراج النظام من حالته
- ❌ اعتبار 200 OK دليلاً على أي شيء
- ❌ محاولة الإصلاح بتعديل كود على عجل بينما مركز مفتوح

---

## 8. بعد أي حادث — إلزامي

1. سطر زمني بالوقائع من Audit Log.
2. الفرق بين المتوقع والفعلي، رقمياً.
3. أي قفل كان يجب أن يمنع هذا ولم يمنع؟
4. اختبار جديد **يفشل قبل الإصلاح ويمرّ بعده**.
5. تحديث هذا الدليل إن كشف الحادث ثغرة في الإجراء.
6. `docs/INCIDENT_RESPONSE.md` للسجل الكامل.
